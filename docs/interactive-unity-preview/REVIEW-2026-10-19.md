# Review of the interactive Unity preview

Reviewed on 19 October 2026 against the current website and Unity files. Product code was not changed during this review.

## Verdict

**A working, substantial browser prototype exists. The complete source-faithful preview requested by the user is still PARTIAL.** Several important screens are simplified or explicitly omit their actual fields. Passing smoke tests do not close those gaps.

The immediate delivery problem has been addressed: a local HTTP server was started on port 8879 and the preview was opened in Codex's browser. It must remain running for these links to work:

- [DGS preview](http://127.0.0.1:8879/Dialogue%20Graph%20System/preview/index.html)
- [AI Providers preview](http://127.0.0.1:8879/AI%20Providers/preview/index.html)
- [Node gallery](http://127.0.0.1:8879/Dialogue%20Graph%20System/preview/index.html?surface=node-gallery)

The browser-check script starts an ephemeral server on a random port and closes it after the checks (`scripts/check-unity-preview-render.mjs:70`, `:162`). Running that script does not leave an interactive preview running for the user. The implementation needed a clear local-server handoff, not more test screenshots before the first preview could be seen.

## What has actually been built

- Plain HTML/CSS/ES-module implementation, consistent with the site's architecture.
- Eight window groups: DGS, AI Providers, Banter, Sound, UI Themes, Inspectors, DGS AI Assistant, and DGS dialogs.
- 58 exported surface entries across those groups. Entries are routes, not proof of complete coverage of the corresponding Unity interface.
- 20 node kinds in the gallery. The visual graph remains an example, without real graph export or execution, as requested.
- Shared controls, in-memory sample state/reset, example modal feedback, and product-specific styles.
- 17 tutorial embeds across 13 DGS/AI Providers pages, using the shared preview modules.
- A coverage/source-hash ledger and maintenance/verification notes.

The work is reusable. It does not need to be thrown away. The next effort should close missing fields and source mismatches rather than add more windows or tutorial placements.

## Findings, in priority order

### [P1] The generic SO inspector explicitly omits the asset fields

**Website:** `assets/unity-preview/surfaces/inspectors.js:369-410`, especially line 401.

The `dgs-asset` route offers 14 asset targets, including Text/Choice/Audio/Input settings, delivery presets, environments, scene context, voice tables and localization assets. It renders a header and a message stating that the field list is "not reproduced here". Selecting another asset changes its identity/documentation topic; it does not reveal the real inspector controls.

**Unity reference:** `Assets/DialogGraphSystem/Scripts/Editor/Inspectors/DgsAssetSOEditors.cs:16-22` calls `InspectorElement.FillDefaultInspector`, which actually renders the selected asset's serialized fields. The data types and nested drawers supply that visible content.

**Impact:** the main request—seeing all inspector details and trying their controls—is not satisfied for these assets. A header is not a complete inspector preview. Rendering a Settings window elsewhere does not reproduce that asset's standalone inspector layout either.

**Next change:** port the serialized fields of each actual target, including nested/conditional controls and tooltips, reusing shared field builders. Track target-by-target field coverage. Stop counting this shared header route as complete SO coverage.

### [P1] The Character workbench is a summary form rather than the actual authoring UI

**Website:** `assets/unity-preview/surfaces/definitions.js:65-81`.

The rendered Character detail has Name, Role, Description, Voice direction, Tags and Usage. Browser inspection confirmed that this is the visible form, not a collapsed full workbench.

**Unity references:**

- `Assets/DialogGraphSystem/Scripts/Editor/Inspectors/DialogCharacterSOEditor.cs:22-45`.
- `Assets/DialogGraphSystem/Scripts/Editor/View/Elements/DialogCharacterCastElement.cs:52-80`, `:123-184`, and the pronunciation UI beginning around line 406.
- `Assets/DialogGraphSystem/Scripts/Runtime/Definitions/DialogCharacterSO.cs:32-100`.

The real UI includes character identity, portrait, writing context, voice guidance/pronunciation, preset and inline delivery, state responses, physical baselines, delivery preview and Banter library content. Most of that cannot be reached in this browser form, and no standalone Character inspector entry supplies the missing authoring body.

**Impact:** readers cannot inspect the SO's most important sections, despite the Characters workspace appearing to be present.

**Next change:** reproduce the actual section structure and controls from the workbench and inspector owners, then reuse that renderer in both hosts. Check other short Definitions forms for the same summary-only substitution.

### [P1] The node gallery substitutes invented/simplified controls for the real node views

**Website:** `assets/unity-preview/surfaces/nodes.js:69-81`, `:150-188`; `assets/unity-preview/nodes.css:33-46`, `:90-94`.

`nodeBody` returns summary lines such as "Speaker · Dialog text" and "Rig ID · Blend Duration" instead of reconstructing the source node's controls. All seven camera types share one generic detail form. The gallery thumbnails are title cards; the selected node is also a reduced representation.

A confirmed semantic error is **Wait For**: the preview displays "Wait duration" and "Wait for input". The real `WaitForNodeView.cs:102-145` exposes Wait for mode, Event ID, Variable, Type and Operator, with additional conditional comparison/fallback controls. The runtime type at `Assets/Beka Forge/Dialogue Graph System/Nodes/Runtime/WaitForNode.cs:9-27` waits for a gameplay event or variable condition, not a duration/input flag. The incorrect fields were also observed directly in the browser.

Geometry is also a deliberate redesign: the browser uses 200px canvas nodes and a 260px preview maximum, while the source `DialogNodeView.cs:31` specifies a 400px dialogue node containing richer content. `NodeTypes.uss` places the family accent on the title's top edge; the browser puts it on the bottom edge.

**Impact:** all 20 names exist, but the agreed fallback was each node's actual USS view and details. A gallery of summary cards does not satisfy that fallback and can teach incorrect fields.

**Next change:** port each node's real layout and visible controls from its view class and styles, starting with Dialogue, Choice and Wait For. Keep the user's graph-authoring/export exclusions. No graph engine is needed to correct the views.

### [P2] Focused surface URLs repeatedly override user navigation

**Website:** `assets/unity-preview/app.js:50`, `:126-151`; `assets/unity-preview/surfaces/dgs.js:232-270`.

Every rerender receives the original URL surface. The DGS renderer reapplies `settingsCategory` and `mainTab` from that surface on each render, including renders triggered by navigation clicks.

**Reproduced:** open `?surface=settings-text`, then click Audio in the left Settings navigation. The UI rerenders but remains on Text. The original surface selection overwrites the click. Main workspace tabs are similarly forced back by non-home focused routes. The tutorial embeds retain these visible navigation controls and use the same render path.

**Next change:** use a URL surface to initialize selection once, or explicitly update the active route when navigation changes. If an embed is intentionally fixed to one component, remove irrelevant navigation controls instead of displaying controls that cannot work. Add a browser interaction assertion, not merely a render assertion.

### [P2] Gallery node colors are broken in two separate places

**Website:** `assets/unity-preview/surfaces/nodes.js:13-14`, `:20-36`; `assets/unity-preview/nodes.css:33-35`, `:127-147`.

1. `nodeAccentClass` lowercases the name before trying to split camel case, so classes such as `node-cameraswitch` never match `.node-camera-switch`. Eleven multiword kinds miss their intended family selectors.
2. For the other kinds, the class is on the outer gallery card while the inner `.dgs-node` defines its own default accent, overriding inheritance from the card.

**Browser evidence:** all 20 thumbnail title borders computed to the same `rgb(143, 163, 200)` slate color. Start, End, Dialogue, Choice and the other families are therefore not visually differentiated as in the real node styles.

**Next change:** generate the correct class before lowercasing and apply/inherit the family tokens at the actual node element. Verify computed rendered colors for Start, End, Dialogue, Camera and Wait For; a string-presence test will not catch this.

### [P2] Tutorial embedding is present, but field-focused live documentation is not implemented

**Website:** `assets/unity-preview/app.js:47-51`, `:126-151`; existing tutorial iframe markup.

The entry reads only `window`, `surface` and `embed`. It has no field routing/highlighting or field-to-documentation selection. The Text settings page embeds the form beside ordinary static prose, but selecting an individual control does not expose the planned field-specific explanation in the tutorial. A number of controls have useful helper text/tooltips, which is a good starting point, but this does not complete the requested connected field documentation.

**Next change:** after the full source-matched preview is corrected, finish one Text settings field selection/help example using stable field IDs and the same renderer. Expand that pattern only once it works. Do not add another collection of generic embeds first.

## What the passing checks mean

| Check | Observed result | Scope |
|---|---|---|
| `node --test tests/unity-preview.test.mjs tests/site-launch.test.mjs` | **PASS — 21/21** | Ten preview tests and eleven site tests. |
| `node scripts/validate-site.mjs` | **PASS** | 75 HTML files, 791 literal references, 45 resource bindings. |
| `node scripts/check-unity-preview-sources.mjs` | **PASS — 79/79** | Only the 79 files listed in the preview ledger. It does not prove that all required source fields/styles were ported. |
| Local HTTP preview launch | **PASS** | Page returned HTTP 200 and real content rendered in the browser. |
| Live browser sampling | **PARTIAL / defects confirmed** | Home, Definitions/Character, Text settings navigation, node gallery/Wait For, and AI Providers full window. |
| Full native Unity/browser visual comparison | **NOT OBSERVED** | No fresh paired native captures were taken. |

The preview tests validate entry counts/modules, a curated set of strings, a small fake DOM, node-kind names, and a few modal handlers. They do not assert full field coverage, native node hierarchy/geometry, per-type styling, or navigation after a focused route loads. The render script checks for an expected text sentinel and screenshot file size; it does not compare screenshots against Unity.

The smoke tests are useful for catching loading failures. Their current success should not be interpreted as acceptance of the source-faithful preview.

The evidence document also needs cleanup after the implementation is corrected: it reports tutorial rollout and later says only the pilot is embedded. The current files contain 17 embeds on 13 pages. Do not use stale completion prose as a progress measurement.

## Recommended direction for the implementation agent

1. Keep the local preview visible and runnable; deliver a URL after each meaningful slice.
2. Fix the focused-route navigation and node color regressions first. They are small, concrete defects.
3. Replace the generic SO-header placeholder with actual serialized field views.
4. Finish the Character workbench and three representative real node views before expanding more screens.
5. Reconcile every remaining active inspector/node against its source. Count fields and states, not just route names.
6. Compare real Unity and browser captures at matching size/theme. Record the remaining differences.
7. Finish field-linked tutorial help using the same corrected components.

This is a fidelity/completeness pass on the existing implementation, not a request for a rewrite or a working graph editor.

## Review limits

This review does not establish whether the external implementation process is currently running or how its time was spent. It establishes what is present on disk and what worked or failed in the sampled browser session. The ~10,000 lines of preview JavaScript/CSS, many dialogs, tests and embeds show substantial work, but their volume does not establish progress toward one-to-one fidelity.

No implementation fixes, Unity changes, commits, pushes, deployment, provider calls or real graph operations were performed. The local preview server is the only added running service.
