## Remaining defects

### [P1] Canvas ports do not render

In `assets/unity-preview/surfaces/nodes.js`, `renderPorts` consumes `portsIn` and `portsOut`. The canvas supplies `renderPorts({ kind, ...nodePorts(kind) })`, but `nodePorts` returns properties named `in` and `out`.

The live graph's `.dgs-canvas .dgs-port` count was **0**. Edges are visible, but none of the node ports are instantiated. Align the data shape and verify actual rendered port counts/directions, including separate branch outputs.

### [P1] The selected instance's inspector still shows shared/default data

The graph finds `selectedCanvasNode`, but passes type-level `selectedMeta` into `nodeInspector`. The inspector reads/writes a shared `state.inspector` object, not the selected node's fields.

Live reproduction: select **Mara**. Exactly one node highlights and the inspector heading changes to Mara, but Character and Speaker remain **Gate Warden**, with the Warden portrait, dialogue and Line ID.

Bind inspector values to the actual selected instance ID and its fixture values. Keep two Dialogue instances and two Action instances independent. Correct highlight identity alone does not satisfy per-instance details.

### [P1] Graph nodes remain summaries instead of the actual node layouts

The canvas still creates a separate body from `Object.entries(node.fields || {}).slice(0, 4)`. It does not use the richer node renderer used by the gallery. Increasing the limit from three to four lines and widening the cards does not port Unity's node controls, portraits, sections or foldouts.

Use a shared source-faithful node renderer in the canvas and gallery, with the real USS/C# hierarchy. The graph can remain nonfunctional; no execution, export or connection editing is required.

### [P2] Favorites and Recent controls are not applied to the result list

`renderHome` calculates `visible` using scope, search and Uncategorized, but does not filter it using `favoritesOnly` or `recentOnly`. The buttons update those flags and rerender, without changing which rows are returned.

Live reproduction: start with zero favorites, click **Favorites**. The summary remains **7 graph(s) visible | 0 favorite(s) | 2 recent** and all seven rows remain visible.

Apply the selected filters to the same result pipeline and verify empty, favorites-only and recent-only cases. Search currently rebuilds the full view on each keystroke; also check focus/caret retention while correcting this pipeline.

## Other source-level limitations to reconcile

- Branch edges still carry only source/target node IDs and guess labels from ID prefixes; both condition exits display True. Real per-port anchors and labels are not represented.
- Selecting another graph changes `selectedGraph`, but the renderer still always uses `state.exampleGraph`. Clearly identify the fixed example or use matching static fixtures.
- Static positions were retained while nodes grew substantially. Review overlaps and scroll reachability in the browser.
- Some gallery icons are emoji or placeholders rather than the source icon assets. This is not source-matched iconography.
