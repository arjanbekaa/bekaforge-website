# Beka Forge Website 3.0 Launch Design

Date: 2026-08-11
Status: Approved design, awaiting written-spec review

## Goal

Make the Beka Forge public website and documentation accurately represent the current product lineup:

- Dialogue Graph System 3.0.0 is the flagship paid Unity Asset Store product.
- AI Providers for Unity is a published, free Unity Asset Store product.
- Dialogue Graph AI Extension is not published and must be presented only as coming soon.

The result should be simpler than the current partial restructuring, customer-facing, responsive, and safe to publish without erasing the existing dirty worktree.

## Authoritative product states

| Product | Public state | Store destination | Primary public action |
| --- | --- | --- | --- |
| Dialogue Graph System | Available, version 3.0.0, $24.99 | `https://assetstore.unity.com/packages/tools/gui/dialogue-graph-system-332234` | View on Asset Store |
| AI Providers for Unity - Beka Forge | Available, free | `https://assetstore.unity.com/packages/package/384482` | Get free on Asset Store |
| Dialogue Graph AI Extension | Coming soon | None | Preview coming soon |

These states must remain separate. DGS does not require the AI products. AI Providers is an independent reusable provider layer. The AI Extension is an optional future authoring layer and must not have a purchase action.

## Constraints

- Preserve all existing user changes. Do not reset, clean, or restore the dirty worktree wholesale.
- Work within the existing static HTML, CSS, and JavaScript architecture; do not introduce a framework or build pipeline.
- Reuse the supplied brand covers and real Unity editor screenshots.
- Keep detailed AI Extension implementation pages in the repository for future work, but remove them from primary public navigation while the product is coming soon.
- Preserve legacy DGS documentation links where practical through small static redirect pages.
- Avoid claims that are not supported by the shipped Core 3.0.0 and published Providers packages.

## Chosen approach

Use a focused three-product launch site built on the current static restructuring.

This is preferred over a minimal text-only patch because the current pages contain internal implementation language and misleading release states. It is preferred over a complete rebuild because the current structure, styles, product documentation, and media are already useful and the worktree contains extensive uncommitted user work.

## Information architecture

### Root website

- `index.html`: product-focused launch homepage.
- `docs.html`: public documentation hub for DGS 3.0.0 and AI Providers, plus a compact AI Extension coming-soon card.
- `roadmap.html`: concise public roadmap with shipped/current/planned states that do not imply the AI Extension is released.
- `assets/data/textresources.js`: canonical product names, statuses, store URLs, and media paths used by root pages.

### Product documentation

- `Dialogue Graph System/`: full public DGS 3.0.0 documentation.
- `AI Providers/`: full public AI Providers documentation with its store link and free/published status.
- `Dialogue Graph AI Extension/index.html`: coming-soon teaser only.
- Remaining `Dialogue Graph AI Extension/` technical pages: retained but not linked from public navigation or the teaser.

### Compatibility routes

The former public site used `/dgs-docs/`. Add lightweight redirect documents for the legacy entry point and important former pages so existing bookmarks continue to reach the corresponding `Dialogue Graph System/` pages. Redirects must include a clickable fallback link and use relative paths compatible with GitHub Pages.

## Homepage design

### Navigation

Keep the compact Beka Forge header with these public destinations:

- Products
- Documentation
- Roadmap
- Publisher page on the Unity Asset Store

The mobile navigation must remain usable without horizontal overflow.

### Hero

Lead with Dialogue Graph System 3.0.0 rather than a generic publisher statement.

Recommended message:

> Build branching dialogue visually in Unity.

Supporting copy should identify DGS as a node-based editor and runtime system, name version 3.0.0, and avoid mentioning unreleased AI features. Primary action goes to the DGS Asset Store listing. Secondary action opens DGS documentation.

Use the supplied DGS cover or social artwork as the visual anchor, with a real graph-editor screenshot visible nearby or immediately below.

### Product cards

Show exactly three cards in this order:

1. Dialogue Graph System 3.0.0 — Available — $24.99.
2. AI Providers for Unity — Available Free.
3. Dialogue Graph AI Extension — Coming Soon.

Each card uses its product cover, a one-sentence customer benefit, no more than three concise capability bullets, and status-appropriate actions.

The AI Extension card must use a visually distinct coming-soon badge and must not use wording such as "available," "production ready," or "store link pending."

### Supporting sections

- A compact DGS 3.0 feature strip using real editor screenshots.
- A documentation callout linking to the docs hub.
- A small product-boundary explanation stating that Core, Providers, and the future AI Extension are separate products.
- A final Asset Store call to action for available products only.

Remove internal language about folder structures, repository organization, public placeholders, and architectural maintenance from customer-facing copy.

## Documentation hub design

The hub should answer “Which documentation do I need?” rather than describe repository organization.

- DGS 3.0.0 card: full docs, installation, quick start, feature guides, troubleshooting.
- AI Providers card: full docs, setup, provider configuration, API reference, troubleshooting, and live Asset Store action.
- AI Extension card: coming-soon teaser with no link to detailed technical documentation.

Use clear status badges and short dependency notes. DGS remains independent; Providers can be installed independently; the future AI Extension will require DGS and use Providers for transport.

## DGS 3.0.0 documentation updates

- Replace every `Dialogue Graph System v2.0.0` footer with `Dialogue Graph System v3.0.0`.
- Add visible 3.0.0 context to the docs landing page and relevant metadata.
- Ensure installation and getting-started material describe the released Core package, not the unreleased AI Extension.
- Keep the existing architecture, concepts, runtime, editor, settings, import/export, history, API, guide, FAQ, and troubleshooting coverage.
- Remove AI Extension links from Core navigation. If a Core page must mention AI, label it as an optional coming-soon product and do not route readers into unreleased setup steps.
- Add or expose customer-facing support, license, and changelog destinations where absent.

## AI Providers documentation updates

- Use the public product name `AI Providers for Unity` consistently, with `AI Providers` as the short form.
- Mark the product `Available Free` and link to package `384482`.
- Add the live store action to the docs landing page.
- Retain the existing provider assets, request pipeline, settings/keys, public API, architecture, getting-started, and troubleshooting content.
- Clearly explain that users supply their own provider credentials and that API usage may incur third-party costs.
- Avoid calling PlayerPrefs encrypted or secure storage; describe the documented local storage behavior accurately.

## AI Extension coming-soon page

Replace the current documentation index with a standalone teaser page that contains:

- `Coming Soon` status.
- One clear description: optional AI-assisted dialogue authoring for DGS.
- A restrained preview of intended workflows, phrased as planned rather than shipped.
- One approved teaser image.
- Links back to DGS and AI Providers.
- No installation steps, API documentation, purchase button, pricing, version number, or claim of production readiness.

Detailed AI Extension pages remain in the tree but are not discoverable through root, docs-hub, roadmap, DGS, or teaser navigation.

### Dialogue Graph System

- Product cover: `Screenshots/DGS-Cover.png` or the equivalent product brand copy.
- Product card: `Screenshots/DGS-Card.png`.
- Feature screenshots: Launcher, Graph, Nodes, Characters-Actions, Variables, Localization, Runtime Dialogue, Runtime History, and Runtime Settings.

### AI Providers

- Product cover/card: supplied `AIProviders_Cover_1950x1300.png` and `AIProviders_Card.png.png` equivalents.

### AI Extension

- Use only the clean product cover/card or one controlled UI preview.
- Do not use promotional slides that say `Built for developers. Designed for production.` while the product is coming soon.

Images should use descriptive alt text, lazy loading below the fold, fixed aspect ratios to reduce layout shift, and responsive sizing.

## Visual system

- Preserve the established obsidian background, steel surfaces, orange forge accent, and restrained blue/purple product highlights.
- Use Space Grotesk for headings and Inter for body text, with system fallbacks.
- Favor fewer, larger sections over dense nested cards.
- Keep body copy within readable line lengths.
- Maintain visible keyboard focus, semantic heading order, sufficient contrast, and reduced-motion support.
- Support desktop, tablet, and mobile breakpoints without clipped navigation, images, or buttons.

## Copy rules

- Customer benefit first; implementation architecture second.
- Use `Dialogue Graph System 3.0.0`, `AI Providers for Unity`, and `Dialogue Graph AI Extension` consistently.
- Never use `store link pending` in public copy.
- Never label AI Extension as current, available, released, or production-ready.
- Do not imply DGS includes AI authoring.
- Do not imply AI Providers generates dialogue by itself.

## Implementation boundaries

Expected edits are limited to:

- Root homepage, docs hub, roadmap, shared text resources, and their inline/shared styles.
- DGS documentation copy/navigation/version markers and small missing public pages.
- AI Providers landing/navigation/store status.
- AI Extension index/teaser navigation.
- Legacy redirect documents.
- Reuse or copy of already supplied visual assets where the current product folders do not already contain the chosen file.

Avoid unrelated documentation rewrites, source-package changes, deployment configuration changes, or deletion of unused media during this launch pass.

## GitHub-backed public configuration and reports

GitHub Pages remains the hosting layer. The site gains a small public configuration file at `assets/data/site-config.json` so repeated public destinations can be edited through the GitHub web interface without changing page markup.

The configuration may contain only public, non-secret values:

- Publisher Asset Store and YouTube URLs.
- Product Asset Store and video URLs.
- Documentation, support, and social destinations.
- The public GitHub repository and report-issue URL.
- Public product status labels and prices when those values are deliberately shown on the site.

`assets/data/textresources.js` retains validated built-in defaults, applies them immediately, then fetches the JSON configuration from the same GitHub Pages origin. Valid remote values replace defaults and the bindings are applied again. If the request fails, returns invalid JSON, or contains unsupported fields, the built-in values remain active so navigation never disappears.

No password, API key, provider credential, personal access token, webhook secret, or private report data may be stored in the public configuration.

Visitor reports use GitHub Issue Forms rather than a browser-side GitHub API token. Add repository issue templates for website/documentation problems and feature requests, plus a public website action that opens the GitHub issue chooser. Reports are therefore public by design and inherit GitHub spam controls, authentication, labels, and notification behavior.

This is intentionally not a general-purpose server, database, analytics collector, or private support system. Private support remains email-based or can be added later through a separately secured service.

## Verification plan

### Static checks

- Parse every HTML file and confirm all literal local `href` and `src` targets exist.
- Resolve all `data-resource-*` keys used by root pages.
- Search public HTML and shared resources for stale `v2.0.0`, `store link pending`, and contradictory AI Extension availability language.
- Confirm DGS and AI Providers store URLs are present and AI Extension has no store URL.
- Confirm no public navigation points to detailed AI Extension technical pages.
- Validate `site-config.json` against the allowed public schema and confirm all required fallback URLs remain present in `textresources.js`.
- Confirm no secret-like keys or values are present in the public configuration.
- Validate GitHub Issue Form YAML structure and confirm the website report URL opens the repository issue chooser.

### Browser checks

- Serve the repository through a local HTTP server.
- Test homepage, docs hub, roadmap, DGS docs, Providers docs, AI Extension teaser, and legacy redirects.
- Test representative desktop and mobile viewport widths.
- Check navigation, CTA destinations, image loading, keyboard focus, overflow, and console errors.

### Completion criteria

The website is ready only when:

1. DGS is consistently presented as 3.0.0 and available at $24.99.
2. AI Providers is consistently presented as published, free, and linked to package 384482.
3. AI Extension is consistently presented as coming soon with no purchase path or public technical-doc navigation.
4. Customer-facing copy is simpler and contains no repository-maintenance language.
5. All tested links and assets resolve.
6. Major pages render correctly at desktop and mobile widths with no browser console errors.
7. Existing unrelated worktree changes remain preserved.
8. Public URLs can be changed in `site-config.json` without editing HTML, and invalid/unavailable configuration falls back safely.
9. Website and documentation reports open public GitHub Issue Forms without exposing a GitHub token.
