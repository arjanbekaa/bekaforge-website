Settings and Providers

The extension deliberately separates shared project defaults from local authoring preferences and local provider secrets. That separation matters for both team setup and machine-local behavior.

Layer 1: local editor settings

Local authoring preferences live in DialogAiEditorLocalSettings via EditorPrefs. These are machine-local values such as selected provider GUID, prompt sections, max tokens, temperature, structured prompt fields, and debug flags.

Layer 2: shared project asset

Shared defaults live in the project asset DialogAISettings. It provides the default provider reference, optional prompt logging behavior, and graph plan safety limits.

Local prompt structure

The effective system prompt can be assembled from named sections instead of one giant free-text field. The documented sections are Context, Persona, Goals, Constraints, Strict Constraints, and Response.

Provider integration boundary

The AI Extension does not own transport. It relies on AI Providers for provider assets, HTTP requests, and local key storage. The extension stores the selected provider GUID locally and resolves the actual provider asset when it needs to run a command.

Default provider and safety caps

public class DialogAISettings : ScriptableObject
{
    [SerializeField] private Object defaultProvider;
    [SerializeField] private bool logPromptsInEditor = true;
    [SerializeField] private GraphOperationPlanSafetyLimits graphPlanSafetyLimits;
}

Important behavior to document accurately

  • API keys are not serialized into the shared settings asset.
  • The selected provider is local editor state first, shared default second.
  • Safety limits are part of the product behavior, not just a hidden internal default.
  • If multiple DialogAISettings resources exist, the first match wins and a warning is logged.

Provider-backed configuration

The extension keeps selected-provider state locally, but actual provider assets, API key entry, and connection testing live in AI Providers.
