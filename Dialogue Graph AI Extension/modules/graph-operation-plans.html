Graph Operation Plans

The graph operation plan system is the high-safety path for broad requests. Instead of directly mutating the graph from raw model output, the extension asks for a structured plan, checks it, previews it, and only then applies it.

What the plan object contains

[Serializable]
public sealed class GraphOperationPlan
{
    public int schemaVersion;
    public string planId;
    public GraphOperationStatus status;
    public string summary;
    public string clarificationQuestion;
    public List<GraphOperation> operations;
    public List<GraphOperationWarning> warnings;
    public List<GraphOperationCouldNotApply> couldNotApply;
    public bool wasJsonRecovered;
}

What it intentionally does not contain

The plan DTO is symbolic. It does not carry GUIDs, port IDs, positions, or serialized graph data. The editor resolves those local mechanical details later during apply.

Pipeline stages

  1. Route the request into the plan system.
  2. Normalize natural language into a structured plan response.
  3. Post-process deterministic omissions that are safe to infer locally.
  4. Validate forbidden properties, symbolic references, capability constraints, and safety caps.
  5. Show ordered operations, warnings, and blocked items in a preview window.
  6. Apply through a single transaction boundary with re-validation and rollback support.

Safety limit surface

The plan path is backed by GraphOperationPlanSafetyLimits on the shared DialogAISettings asset. Defaults are intentionally conservative and cap operations, new graph nodes, choice constructs, action nodes, and dependency depth.

public const int DefaultMaxOperationsPerPlan = 12;
public const int DefaultMaxNewGraphNodes = 8;
public const int DefaultMaxDialogueNodes = 6;
public const int DefaultMaxChoices = 4;

Strict vs partial apply

The preview surface can expose operations that could not safely apply. That is why this page distinguishes strict apply from partial apply instead of implying every broad prompt is fully executable.

Residual limitation

Rollback is graph-focused and undo-backed, but newly created asset artifacts may still remain after a failed apply. That limitation is worth documenting because it affects real editor cleanup work.

Detected graph plan route

Broad prompts are surfaced as detected graph plans first so the author can review structure before any graph mutation applies.
