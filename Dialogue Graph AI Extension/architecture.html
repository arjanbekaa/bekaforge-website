Architecture

The AI Extension is not a raw "send prompt, mutate graph" feature. It layers floating-panel UI, bridge integration, routing, prompt construction, draft parsing, preview review, and only then controlled graph mutation.

High-level flow

User instruction
  -> DGS bridge surface
  -> route detector
  -> prompt builder
  -> AI Providers transport
  -> draft parser
  -> preview window
  -> mutation service after approval

DGS owns the host editor

The core integration contract is IDialogGraphAiBridge. DGS owns the graph editor host. The AI Extension implements the bridge and injects the floating AI Assistant workflow and quick actions without taking over the whole editor.

Code naming versus user-facing naming

The main implementation class still uses the name DialogGraphAiSidebarContent, but the product surface presented to users is the floating AI Assistant panel. This documentation uses the panel wording for product behavior and keeps the older sidebar name only when referring to code.

public interface IDialogGraphAiBridge
{
    bool IsAvailable { get; }
    VisualElement CreateAiSidebarContent(IDialogGraphOwner owner);
    bool TryRunQuickAction(IDialogGraphOwner owner, DialogGraphAiQuickAction action, out string error);
    void OpenSettings();
}

Routing is multi-stage

The prompt field does not represent one uniform workflow. Routing is split between editor tool routes, graph operation plans, and legacy direct command execution.

  • Editor tool routing opens tabs, repairs layout, or redirects localization work.
  • Graph operation plan routing handles broad multi-step authoring requests.
  • Legacy direct commands handle targeted rewrite, grammar, branch continuation, action insertion, and similar narrow flows.

Preview before mutation

The preview/apply boundary is the central design rule. The AI produces drafts and plans. The editor owns GUIDs, positions, links, undo, integrity checks, save state, and final graph mutation.

Graph mutation boundaries

Forbidden properties are filtered before the graph is touched. The model is not allowed to author GUIDs, coordinates, ports, or serialized graph JSON. That boundary is part of the safety contract, not just a UI preference.

Why this matters publicly

This architecture explains why the extension can be described as an authoring assistant instead of a freeform graph generator. The implementation is deliberately constrained, reviewable, and editor-owned.
